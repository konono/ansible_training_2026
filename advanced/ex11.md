# 応用演習 11 - [オプション] Windowsノードの管理

[前に戻る](./ex10.md)

------

この演習はオプションです。AnsibleはLinuxだけでなく、Windowsノードも管理できます。この演習では、WinRM接続の設定、Windowsモジュールの使用方法、そしてLinuxとWindowsの混在環境での管理方法について学びます。

---

**前提条件**:
- **Windows 11 ラップトップのみ** で実行可能です（nested virtualization + KVM 必須）
- macOS では KVM を提供できないため動作しません
- dockur/windows コンテナが起動済みであること
- pywinrm がインストール済みであること

Windows コンテナのセットアップについては、[Windows コンテナ環境 README](../containers/windows/README.md) を参照してください。

---

## Section 1: Windowsインベントリの設定

### Step 1: 作業ディレクトリの作成

```bash
$ mkdir ~/windows-lab
$ cd ~/windows-lab
```

### Step 2: pywinrm のインストール確認

AnsibleがWindows に WinRM で接続するために必要なPythonパッケージです。

```bash
$ pip install pywinrm
```

```
Successfully installed pywinrm-0.4.3 ...
```

既にインストール済みの場合は `Requirement already satisfied` と表示されます。

### Step 3: インベントリファイルの作成

```bash
$ vi inventory.yml
```

```yaml
all:
  children:
    windows:
      hosts:
        winnode:
          ansible_host: 172.20.0.20
          ansible_user: ansible
          ansible_password: "AnsiblePass123!"
          ansible_connection: winrm
          ansible_port: 5985
          ansible_winrm_transport: ntlm
          ansible_winrm_server_cert_validation: ignore
```

### Step 4: 各設定パラメータの解説

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| `ansible_connection` | `winrm` | SSH ではなく WinRM プロトコルで接続する |
| `ansible_port` | `5985` | WinRM の HTTP ポート（HTTPS の場合は `5986`） |
| `ansible_winrm_transport` | `ntlm` | 認証方式（`basic`, `ntlm`, `kerberos` 等） |
| `ansible_winrm_server_cert_validation` | `ignore` | SSL証明書の検証をスキップ（テスト環境用） |

---

**本番環境での注意**: 本番環境では以下の点に注意してください。

- `ansible_port: 5986`（HTTPS）を使用する
- `ansible_winrm_transport: ntlm` または `kerberos` を使用する
- `ansible_winrm_server_cert_validation: validate` で証明書を検証する
- パスワードは Ansible Vault で暗号化する

---

### Step 5: ansible.cfg の作成

```bash
$ vi ansible.cfg
```

```ini
[defaults]
inventory = ./inventory.yml

```

## Section 2: 接続テスト — win_ping

### Step 1: win_ping による接続確認

Linux の `ping` モジュールに対応する Windows 用モジュールが `win_ping` です。

```bash
$ ansible winnode -m ansible.windows.win_ping
```

```
winnode | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

`pong` が返ってきたら、WinRM 接続が正常に動作しています。

### Step 2: トラブルシューティング

接続に失敗した場合は、以下を確認してください。

```bash
# WinRM ポートの応答確認
$ curl http://172.20.0.20:5985/wsman
```

レスポンスが返ってこない場合は、Windows コンテナが起動していないか、WinRM が有効化されていない可能性があります。

よくあるエラーと対処法:

| エラーメッセージ | 原因 | 対処 |
|----------------|------|------|
| `winrm or requests is not installed` | pywinrm 未インストール | `pip install pywinrm` |
| `Connection refused` | WinRM 未起動 or ポート未開放 | コンテナ起動確認、`http://localhost:8006` で状態確認 |
| `401 Unauthorized` | 認証情報が間違っている | ユーザー名・パスワードを確認 |
| `Connection timed out` | ネットワーク到達不可 | IPアドレスとネットワーク設定を確認 |

```bash
# 詳細なデバッグ出力で原因を調査
$ ansible winnode -m ansible.windows.win_ping -vvvv
```

## Section 3: win_service — サービス管理

### Step 1: サービスの一覧表示

```bash
$ vi list_services.yml
```

```yaml
---
- name: Windows サービスの管理
  hosts: winnode
  gather_facts: false
  tasks:
    - name: W32Time サービスの状態を確認
      ansible.windows.win_service_info:
        name: W32Time
      register: service_info

    - name: サービス情報を表示
      ansible.builtin.debug:
        var: service_info.services[0]
```

```bash
$ ansible-playbook list_services.yml
```

```
TASK [サービス情報を表示] *****************************************************************
ok: [winnode] => {
    "service_info.services[0]": {
        "display_name": "Windows Time",
        "name": "W32Time",
        "start_mode": "manual",
        "state": "stopped",
        ...
    }
}
```

### Step 2: サービスの起動

```bash
$ vi manage_service.yml
```

```yaml
---
- name: Windows サービスの操作
  hosts: winnode
  gather_facts: false
  tasks:
    - name: W32Time サービスを起動
      ansible.windows.win_service:
        name: W32Time
        state: started

    - name: W32Time サービスの状態を確認
      ansible.windows.win_service_info:
        name: W32Time
      register: service_after

    - name: 起動後の状態を表示
      ansible.builtin.debug:
        msg: "W32Time: {{ service_after.services[0].state }}"
```

```bash
$ ansible-playbook manage_service.yml
```

```
TASK [W32Time サービスを起動] *************************************************************
changed: [winnode]

TASK [起動後の状態を表示] *****************************************************************
ok: [winnode] => {
    "msg": "W32Time: running"
}
```

### Step 3: サービスの停止と自動起動設定

```yaml
  tasks:
    - name: サービスを停止
      ansible.windows.win_service:
        name: W32Time
        state: stopped

    - name: サービスを自動起動に設定して起動
      ansible.windows.win_service:
        name: W32Time
        state: started
        start_mode: auto
```

| state の値 | 動作 |
|-----------|------|
| `started` | サービスを起動する |
| `stopped` | サービスを停止する |
| `restarted` | サービスを再起動する |
| `absent` | サービスを削除する |

## Section 4: win_package / win_chocolatey — ソフトウェア管理

### Step 1: win_package によるソフトウェアのインストール

`win_package` モジュールは MSI や EXE インストーラーを使ってソフトウェアをインストールします。

```bash
$ vi install_package.yml
```

```yaml
---
- name: win_package でソフトウェアをインストール
  hosts: winnode
  gather_facts: false
  tasks:
    - name: 7-Zip をインストール
      ansible.windows.win_package:
        path: https://www.7-zip.org/a/7z2301-x64.msi
        product_id: '{23170F69-40C1-2702-2301-000001000000}'
        state: present
      register: install_result

    - name: インストール結果を表示
      ansible.builtin.debug:
        var: install_result
```

### Step 2: Chocolatey のインストール

[Chocolatey](https://chocolatey.org/) は Windows 用のパッケージマネージャで、Linux の `yum` や `apt` に相当します。

```bash
$ vi install_chocolatey.yml
```

```yaml
---
- name: Chocolatey のセットアップ
  hosts: winnode
  gather_facts: false
  tasks:
    - name: Chocolatey をインストール
      chocolatey.chocolatey.win_chocolatey:
        name: chocolatey
        state: present

    - name: Chocolatey のバージョンを確認
      ansible.windows.win_command: choco --version
      register: choco_version
      changed_when: false

    - name: バージョンを表示
      ansible.builtin.debug:
        msg: "Chocolatey {{ choco_version.stdout | trim }}"
```

```bash
$ ansible-playbook install_chocolatey.yml
```

```
TASK [Chocolatey をインストール] **********************************************************
changed: [winnode]

TASK [バージョンを表示] *******************************************************************
ok: [winnode] => {
    "msg": "Chocolatey 2.2.2"
}
```

### Step 3: Chocolatey でパッケージをインストール

```bash
$ vi install_apps.yml
```

```yaml
---
- name: Chocolatey でアプリケーションをインストール
  hosts: winnode
  gather_facts: false
  tasks:
    - name: Notepad++ をインストール
      chocolatey.chocolatey.win_chocolatey:
        name: notepadplusplus
        state: present

    - name: Git をインストール
      chocolatey.chocolatey.win_chocolatey:
        name: git
        state: present

    - name: 複数パッケージを一括インストール
      chocolatey.chocolatey.win_chocolatey:
        name:
          - 7zip
          - curl
        state: present

    - name: インストール済みパッケージを確認
      ansible.windows.win_command: choco list
      register: choco_list
      changed_when: false

    - name: パッケージ一覧を表示
      ansible.builtin.debug:
        var: choco_list.stdout_lines
```

```bash
$ ansible-playbook install_apps.yml
```

## Section 5: 混在環境（Linux + Windows）の管理

### Step 1: 混在インベントリの作成

Linux と Windows の両方を含むインベントリを作成します。

```bash
$ vi mixed_inventory.yml
```

```yaml
all:
  children:
    linux:
      vars:
        ansible_user: root
        ansible_ssh_pass: password
        ansible_port: 22
      children:
        web:
          hosts:
            node1:
              ansible_host: 172.20.0.11
            node2:
              ansible_host: 172.20.0.12
            node3:
              ansible_host: 172.20.0.13
        loadbalancer:
          hosts:
            lb:
              ansible_host: 172.20.0.14
    windows:
      hosts:
        winnode:
          ansible_host: 172.20.0.20
          ansible_user: ansible
          ansible_password: "AnsiblePass123!"
          ansible_connection: winrm
          ansible_port: 5985
          ansible_winrm_transport: ntlm
          ansible_winrm_server_cert_validation: ignore
```

### Step 2: グループごとに異なる Play を実行

```bash
$ vi mixed_site.yml
```

```yaml
---
# Linux ノード向け — nginx のセットアップ
- name: Linux Web サーバーのセットアップ
  hosts: web
  become: true
  gather_facts: true
  tasks:
    - name: nginx をインストール
      ansible.builtin.package:
        name: nginx
        state: present

    - name: nginx を起動
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true

    - name: Linux ホスト情報を表示
      ansible.builtin.debug:
        msg: >
          [Linux] {{ inventory_hostname }}
          ({{ ansible_distribution }} {{ ansible_distribution_version }})
          — nginx: running

# Windows ノード向け — IIS のセットアップ
- name: Windows Web サーバーのセットアップ
  hosts: windows
  gather_facts: true
  tasks:
    - name: IIS をインストール
      ansible.windows.win_feature:
        name: Web-Server
        state: present
        include_management_tools: true
      register: iis_install

    - name: IIS を再起動（必要な場合）
      ansible.windows.win_reboot:
      when: iis_install.reboot_required

    - name: IIS サービスを起動
      ansible.windows.win_service:
        name: W3SVC
        state: started
        start_mode: auto

    - name: Windows ホスト情報を表示
      ansible.builtin.debug:
        msg: >
          [Windows] {{ inventory_hostname }}
          ({{ ansible_distribution }} {{ ansible_distribution_version }})
          — IIS: running
```

### Step 3: 全ホスト共通の ping テスト

Linux と Windows では ping モジュールが異なりますが、条件分岐で対応できます。

```bash
$ vi mixed_ping.yml
```

```yaml
---
- name: 全ホストの接続テスト（Linux）
  hosts: linux
  gather_facts: false
  tasks:
    - name: Linux ホストに ping
      ansible.builtin.ping:

    - name: 結果を表示
      ansible.builtin.debug:
        msg: "[Linux] {{ inventory_hostname }} — OK"

- name: 全ホストの接続テスト（Windows）
  hosts: windows
  gather_facts: false
  tasks:
    - name: Windows ホストに win_ping
      ansible.windows.win_ping:

    - name: 結果を表示
      ansible.builtin.debug:
        msg: "[Windows] {{ inventory_hostname }} — OK"
```

```bash
$ ansible-playbook -i mixed_inventory.yml mixed_ping.yml
```

### Step 4: Windows でよく使うモジュール一覧

| モジュール | 説明 | Linux での対応 |
|-----------|------|---------------|
| `win_ping` | 接続テスト | `ping` |
| `win_copy` | ファイルコピー | `copy` |
| `win_template` | テンプレート配置 | `template` |
| `win_file` | ファイル/ディレクトリ操作 | `file` |
| `win_service` | サービス管理 | `service` |
| `win_package` | MSI/EXE インストール | `package` |
| `win_chocolatey` | Chocolatey パッケージ管理 | `yum` / `apt` |
| `win_feature` | Windows 機能の有効化 | — |
| `win_reboot` | Windows の再起動 | `reboot` |
| `win_user` | ユーザー管理 | `user` |
| `win_group` | グループ管理 | `group` |
| `win_command` | コマンド実行 | `command` |
| `win_shell` | PowerShell 実行 | `shell` |
| `win_firewall_rule` | ファイアウォールルール | `firewalld` |
| `win_scheduled_task` | タスクスケジューラ | `cron` |

---

**ポイント**: Windows モジュールは `win_` プレフィックスが付いています。Linux 用のモジュール（`copy`, `service` 等）は Windows ノードでは動作しません。Play の `hosts:` を適切にグループ分けし、OS に応じたモジュールを使い分けてください。
